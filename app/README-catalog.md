# 自有片库：换播放地址，不丢续播记录

适用于在 Apple TV 或 Mac 上导入有播放权限的 HTTPS JSON 分集清单。两台设备各自保存播放记录，不会跨设备同步。

1. 片库维护人给清单分配一个长期不变的 `catalogId`，如 `company-training`。它是同一个 HTTPS 网站内的片库标识，不是登录密码。长度 1–80，只用英文字母、数字、点、下划线或连字符；同一网站上的不同用户或片库不要共用。
2. 每个节目有固定的 `id`，每集也要有自己的固定 `id`。只改显示名或 `streamURL` 时，别改这两层 ID。已删除的节目/集 ID 不要指给另一部内容。
3. 在 App 选「导入片源」→「JSON 短剧清单」，填入本人有权使用的完整清单地址，再点「导入」。清单授权或播放地址到期时，请用维护人给出的新地址重新导入，不是自动续期。
4. 新旧清单的最终 HTTPS 主机和有效端口、`catalogId`、节目 ID 和分集 ID 都相同时，新播放地址沿用该集原先的续播进度。更换主机、端口或片库 ID 会视为另一片库；旧条目没有自动删除。没有提供 `catalogId` 的既有清单保持原行为；直接粘贴的视频地址也不会擅自忽略查询参数。第一次把旧清单改成带 `catalogId` 的清单会建立新身份，旧进度不自动迁移。

下面为**格式示意，不可播放**；替换为你有权提供的 HTTPS 媒体地址后发布。不要把带密钥的清单提交到公共仓库。

```json
{
  "catalogId": "company-training",
  "shows": [{
    "id": "safety",
    "title": "安全培训",
    "subtitle": "公司授权片库",
    "episodes": [
      {"id": "intro", "title": "第 1 集", "streamURL": "https://media.example/first.mp4"},
      {"id": "practice", "title": "第 2 集", "streamURL": "https://media.example/second.mp4"}
    ]
  }]
}
```

若清单由多人托管在同一个域名（例如公共共享 CDN），这个域名不能替你确认内容发布者身份。只导入你信任的清单，并使用专属域名或彼此独立的片库标识；此机制用于本机续播匹配，不是认证系统。
